## 发布范围与策略审查

- Linux x86_64/aarch64 的新入口先获取并核验固定 0.5.0 核心，再用原生 download
  下载业务脚本。macOS、DSM、华硕、QNAP、其他架构保留此前入口分支；Windows GUI 不变。
- 核心与推荐清单仍拒绝全部重定向。不可变业务脚本允许核心现有的 HTTPS 重定向，
  但必须通过 TLS、精确大小和固定 SHA256，执行前再复验；HTTP 降级和坏摘要测试拒绝。
- 本次工程审查接受此差异用于测试环境：下载地址不含 Token，重定向不能改变获准执行
  的脚本字节，不能为推荐清单或核心选择新版本。不宣称与旧拒绝所有重定向策略相同。
  正式上线仍须独立评审，不能由测试站激活自动推广。
- `package-ddnsto-recommendation.py` 默认仍为 shell-first。`--native-first` 显式打包；
  `review.json` 保持生成时的保守未发布/待验收状态，本部署记录补充实际发生的发布证据，
  不回写已发布不可变候选。未开放环境变量指定核心、镜像或跳过校验的后门。

## 自动化与失败项归因

- 推荐/自动平台相关 `tests/ddnsto*test.py`：153 项，121 通过、32 跳过。
- Wget 入口：51 项全部通过；修复了真实核心测试恢复 TLS 夹具时误用父类
  `key.pem` 路径的问题。子类使用独立 CA/leaf，恢复时现在使用各自的证书及密钥。
- 取消协调：6 项通过，新增下载子进程取消时先等待退出再清理工作目录的用例。
  真实 0.5.0 下载过程中的 TERM 拒绝执行安装器也已单独验证。
- 原生契约：0.5.0 为 14 通过/13 不具备命令而跳过；0.6.4 为 27 通过。
  0.6.4 仅用于能力研究，没有升级线上核心。
- OpenWrt 生命周期：29 项通过，含模拟新装、更新、配置保持、失败恢复及信号。
- macOS 隔离模拟：86 项通过；ASUS：96 通过、2 跳过；群晖自动流程 13 项、
  下载契约 16 项通过。这些不是新增的 macOS/ASUS 真机证据。
- 独立一次性 Linux 容器：18 项托管生命周期、4 项自动 Linux 测试通过，使用真实
  0.5.0、隔离文件系统和模拟 systemd。不是实际 systemd 或客户端联网验收。
  首轮夹具复制权限及缺 jq 问题已处理后重跑；安装依赖只发生在容器内，随后断网。
  容器已删除，未挂载宿主业务目录或修改宿主服务。
- 生成一致性、Shell 语法及 `git diff --check` 通过。

不能宣称所有历史测试通过：直接对 `ddnsto/tests/*test.py` 做统一 discover
曾得到 476 项、105 failures/2 errors（包含 Wget TLS 夹具连锁失败及老入口用例）。
`ddnsto_test.py` 是接收 native 路径的隔离套件驱动，不支持 unittest 自动导入；
其他旧 flat-path 测试仍引用已迁移接口。已在干净 HEAD 的临时归档中复现
entry_dispatch 6 项失败、linux_lifecycle 15 项失败、install_rules 1 项失败。
这些不是本轮复用改造引入；未通过放宽安全校验、删除断言或将失败改为跳过来掩盖。
