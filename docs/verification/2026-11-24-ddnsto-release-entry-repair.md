# DDNSTO 0.3.1 标准入口兼容修复

状态：本地候选，随本轮修复提交；未推送、未部署正式环境。源基线 `993636b`。

## 范围和授权

用户授权修复一键脚本，使用既有测试设备验证。不修改 zsetup 核心、不修改正式下载站，
不更换账号或清除配置、不降级客户端。客户端推荐版本及产品摘要未改变。
保留 `versions/0.3.0/` 原字节，新增 `versions/0.3.1/`；公开名字仍为
`install.sh`、`install.ps1`、`install.md`。

## 复现和修复

| 问题 | 证据 | 处理 |
| --- | --- | --- |
| 全量索引读取失败 | Linux 0.6.4：128 条记录可以列出，129 条即 exit 17，旧配置有 131 条；压缩 JSON 不改变结果 | 合并 DDNSTO CentOS/RHEL yum/dnf 路由，127 条；生成器超过 128 条拒绝构建 |
| 原生安装协调路径拒绝版本门槛 | OpenWrt 0.6.4、Windows 0.6.5：`--index` 的 min_version=0.5.0 拒绝，0.1.0 可进入；完整产品配置安装路径仍失败 | 从唯一 app.json/生成配置派生 DDNSTO 原生兼容索引，公开入口使用现有 `install --index`；版本安装器先独立验证真实核心 >=min_zsetup，再执行业务 |
| Windows 参数位置绑定 | `-Action status` 被旧载荷绑定到 Token/TokenFile，报告二者冲突 | 新版本载荷解析允许的命名参数，拒绝重复/未知/缺值，用哈希表传入原业务函数；统一父子 UTF-8 输出 |
| 群晖 noexec | `/tmp` 含 noexec，旧通用自举先于业务缓存选择 | 在任何自举执行前选择并校验私有缓存；管理员使用 `/var/lib/ddnsto-installer`，不改挂载和已有权限 |
| 群晖、华硕原生识别 | 两台设备的 0.6.4 context 均为 os/device/package_manager=unknown；通配及 unknown 索引探测也未进入业务 | 固件指纹确认后，由 zsetup 下载并校验生成器固定的版本载荷，再执行既有平台适配；不伪造 context、不因任意安装失败切换路径 |
| 华硕旧 Shell | 固件无 `command` 内建，外层 curl 成功但工具探测失败 | 共享自举探测使用 `type`；私有 JFFS 存储检查提前。旧 armsoft 保留 HTTPS + 固定大小/SHA 校验路径，不尝试运行不兼容的新核心 |
| macOS 发布缺包 | stable-macos=0.6.5，其 SHA256SUMS 只有 Windows 文件，没有 zsetup-macos-aarch64 | 明确 exit 11，报告发布缺失，不再尝试 HTTP；实际安装仍需运维修复平台 stable/产物 |

兼容索引放在 `apps/zsetup/ddnsto-index.json`、`ddnsto-index-windows.json`，是当前核心的
原生 Index 协议，不是重新引入推荐清单。版本、路由、URL、SHA 来自同一生成结果，不另存
客户端版本配置。产品配置中的 min_version 仍为 0.5.0；兼容索引的 0.1.0 只是当前协调器
接受的门槛，实际核心能力门槛由版本安装器保护。未读取或修改核心源码，不能把对照结果
扩大为所有未来版本核心的内部实现结论。

## 发布前条件

1. 运维提供完整的 macOS 核心平台发布，检查二进制、摘要、版本、架构，再更新 stable-macos。
   不把 Linux/Windows 发布版本号直接复制到 macOS 指针，不把旧 0.3.0 核心冒充满足 >=0.5.0。
2. 华硕使用经审核、实际可获得且版本一致的插件包补充新装/升级验收；不得覆盖现有更高版本。
3. 发布时一起同步新不可变版本、两个原生兼容索引、标准入口、产品配置和 SHA256SUMS。
   先载荷与索引，再入口；不能只上传 install.sh。
4. 源码提交、精确 release ID 的正式发布分别取得授权；之后从正式域名逐台回归。
5. 目前不移除控制台“回归未通过”提示，不宣称全平台已经恢复。

读取索引、低版本核心拒绝、私有存储失败、Windows 参数桥接和生成入口路径。

配置下载、原生索引选择、SHA 校验和版本载荷 --help，不操作宿主机服务。

最终检查结果：

- 新增 bootstrap 回归测试 13/13 通过；真实 0.6.4 入口集成测试通过，包含平台直达路径的摘要篡改拒绝和临时文件清理。
- DDNSTO 专项发现 147 项，119 项执行通过、28 项跳过。Shell 兼容专项 4 项中 2 项通过、2 项跳过；未提供历史 Bash 4.2，不能声明该版本已验证。
