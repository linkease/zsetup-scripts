# Linux systemd 空间预算与 Zig 新装

状态：0.3.5 本地候选，未提交、部署或操作真机服务。

复用 `platform-releases.json` 生成的 Linux 产品大小，不引入第二份版本数据。
标准客户端保留既有管理方式；新装空间不足时选择审核的 Zig 4.2.1 裸二进制。
Zig 仍使用统一服务事务、JSON 管理配置和维护动作，启动前生成私有 YAML。
已有客户端不自动跨 Go/Zig 迁移，不静默降级，不支持 Zig 测试业务环境切换。

## 预算

- D：标准归档 16757733 字节。
- E：本架构二进制按 4 KiB 向上取整，再加 256 KiB 元数据与包装脚本余量。
- root：`D + 2E`，加 10% 向上取整和 8 MiB。
- sudo 准备：`2D + 2E`，加 10% 向上取整和 8 MiB，保留跨用户复制成本。
- 已有版本留在原版本目录，不以未来清理抵扣所需空间。

| 架构 | root 新增预算（字节） | sudo 准备预算（字节） |
|---|---:|---:|
| x86_64 | 37410275 | 55843781 |
| aarch64 | 51774128 | 70207634 |

Zig：D 为审核裸二进制大小，E 为 D 按 4 KiB 向上取整再加 256 KiB。
root 为 `ceil((D + 2E) × 1.1) + 1 MiB`；sudo 为
`ceil((2D + 2E) × 1.1) + 1 MiB`。没有归档解压，但保留下载、候选和提交副本预算。

| Zig 架构 | root 新增预算（字节） | sudo 准备预算（字节） |
|---|---:|---:|
| x86_64 | 4111284 | 4939215 |
| aarch64 | 6528424 | 8160490 |

需要已有 jq，不自动增加包依赖。普通用户准备阶段只验证可读的受保护安装凭据，
不读取 root 私有配置或 unit；提权后再验证全部安装归属、账号和实际服务定义。
审核版本、大小和摘要仍只维护在 `platform-releases.json`。

以上不包含入口和 zsetup 自举已占空间，也不是全设备最低容量承诺。
显式选择未审核历史版本继续使用旧预算；其他应用及平台不改变默认上限。

服务隔离测试原本固定运行 0.3.0，已改为读取 app.json 当前候选。

当前自定义服务路径应报 E_OPTIONS，并且不得操作系统服务；已同步该断言。
实际客户端和 systemctl 在该套件中是 fixture，不代表 systemd/Zig 真机验收。

修正后使用真实 zsetup 0.6.4 在独立 mount namespace/chroot 中复跑 DDNSTO 服务
套件通过，涵盖安装、缓存、健康检查、失败回滚、路径保护和未归属安装拒绝。
有界解包测试（膨胀包、累计上限、旧产物保留和临时清理）与公共树检查通过。
真实 zsetup 下进程模式回归 22 项通过；产品配置 10 项、OpenWrt 预算 12 项、
临时目录策略 5 项通过。Shell 语法和 diff 检查通过。

- 产品选择 8 项覆盖空间足够/不足、sudo 额外副本、已有版本保留、拒绝跨实现迁移、
  显式标准版与测试业务环境限制。

  重复执行、停止与启动均通过；2 项实二进制测试通过。该结果不代表 systemd 的容量下限。
- 公共事务测试覆盖正常/失败清理、TERM、子进程退出、并发隔离、陈旧锁和私有目录保护。
- `service_storage_test.py` 的 DDNSTO 隔离套件通过：保留标准版回归，新增 Zig
  新装、首次启动失败回滚后同命令重试、启停/重启、配置变更、账号不符拒绝、修复、
  重复安装、更新保持 Zig 与卸载。生成 unit 通过 `systemd-analyze verify`。
  已修复首次失败后空安装标记阻断重试的问题：仅清理本事务创建且已完整回滚的文件，
  未知运行数据和已有设备身份仍保留，不把不明旧安装当成空安装。
- 管理 CLI 26 项通过，构建/产品配置/公共树一致性和 Bash 4.2 POSIX 语法检查通过。
