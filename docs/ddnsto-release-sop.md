# DDNSTO 一键安装推荐版本更新 SOP

适用：调整原生平台推荐版本、修改安装器、准备候选、测试发布、正式发布及回滚。
本流程只发布安装器，不负责构建客户端包。数据与模板边界见 [配置说明](ddnsto-platform-releases.md)。

固定顺序：范围确认 → 产品审核 → 修改配置 → 生成与检查 → 审核并打包 → 测试验收 → 正式发布 → 归档。
未取得下一阶段授权时，停在当前阶段交付材料；本 SOP 本身不授权提交、推送、设备操作或上线。

## 1. 确认范围、建立记录

在仓库根目录检查 `git status --short` 和当前分支，保留已有改动。
从 [发布记录模板](templates/ddnsto-release-record.md) 建立
`docs/verification/YYYY-MM-DD-ddnsto-release-<标识>.md`。
记录目标平台、旧/新客户端版本、包修订号、变更原因、目标环境和授权范围。

完成条件：每个平台的变更明确；有唯一记录；未涉及的平台保持原配置。

## 2. 审核实际产品包

先由客户端发布流程提供产品包；逐项核实真实下载 URL、文件大小、SHA-256、包内版本和架构。
多镜像必须核实实际使用的来源，不能把本地重打包的摘要当作已发布 CDN 摘要。

- Windows CLI：ZIP 与解包后的 EXE 摘要。
- 群晖：客户端版本、SPK 修订号、各 DSM/架构包摘要。
- 华硕：六渠道各自的大小、摘要与包兼容标记；渠道中的实际二进制版本需要核实。
- OpenWrt：standard/lite、opkg/apk、各架构主包及配套 LuCI 包。
- Linux/macOS：归档摘要、包内布局与实际支持架构。

完成条件：所有变更包都有来源证据；缺包、版本不符或兼容性不明时停止，不靠替换版本字符串猜测支持。

## 3. 修改唯一维护源并生成

版本/摘要改 `sources/ddnsto/platform-releases.json`；安装行为改对应
`sources/ddnsto/templates/*.in`。
没有模板的模块直接修改源文件。生成副本不作为人工修改入口。

```sh
python3 -B scripts/build-ddnsto-products.py
python3 -B scripts/build-ddnsto-products.py --check
python3 -B scripts/build.py
python3 -B scripts/build.py --check
git diff --check
git diff --stat
git diff -- sources/ddnsto/platform-releases.json sources/ddnsto/templates
```

同时审查未跟踪文件，`git diff` 不会显示它们。检查生成结果中各平台版本、包路径、摘要、
升级比较和安装后校验一致；保留防降级、账号/身份保护及版本专属兼容门槛。

完成条件：生成与一致性检查通过，变化仅覆盖预定范围。

## 4. 执行本地验证

```sh
python3 -B tests/ddnsto_release_config_test.py
python3 -B -m unittest discover -s tests -p 'ddnsto*test.py'
```

需要真实核心的测试使用已验证的 zsetup 可执行文件设置 `DDNSTO_TEST_NATIVE`；另按修改平台
运行 `tests/apps/ddnsto/` 下相关测试。使用 `sh scripts/check.sh --native-bin /绝对路径/zsetup`
执行标准检查，不需要修改或重编 zsetup 源码。

Shell 入口/生成器变更还必须通过 Bash 4.2 POSIX 模式验证，不能仅用开发机的 `sh -n`。
设置 `DDNSTO_TEST_LEGACY_SHELL` 为已审核的旧 Shell 命令后，执行
`python3 -B tests/ddnsto_shell_compat_test.py`；可使用禁网、只读的隔离容器。
该环境变量仅用于维护者测试，不进入设备安装协议。未提供旧解释器时的跳过不算兼容验证通过。

完成条件：记录命令、通过/失败/跳过数及原因。新失败必须修复；疑似历史失败需与修改前提交对照。
跳过、环境受限或历史失败都不能写为“全量通过”；影响目标平台的验证缺口需在继续发布前明确确认。

## 5. 审核字节、生成本地候选

控制台完整安装站点的正式交付路径已于 2026-11-24 切换为 `apps/ddnsto/`。
步骤 3 的 `scripts/build.py` 同时生成 `i`、`i.ps1`、推荐清单、摘要执行器和 AI 指南，
随 `apps/SHA256SUMS` 一起审核、提交。运行 `tests/ddnsto_apps_site_test.py` 验证完整性及
发布事务。完整 apps 交付使用 [现有发布协调器](apps-release.md)，不能只上传旧 dist。
下述推荐打包命令仅用于隔离候选检查，不再是正式目录的另一份维护源。

先审查差异，再取得两个实际安装器的 SHA-256：

```sh
sha256sum apps/ddnsto/0.2.5/installer.sh sources/ddnsto/install.ps1
python3 -B scripts/package-ddnsto-recommendation.py --help
```

将审核后的摘要代入现有打包命令（尖括号为待填写值，不能原样执行）：

```sh
python3 -B scripts/package-ddnsto-recommendation.py \
  --source-url '<本次确认的HTTPS推荐目录>' \
  --reviewed-shell-sha256 '<审核后的shell摘要>' \
  --reviewed-powershell-sha256 '<审核后的PowerShell摘要>' \
  --output '<不存在的本地候选目录绝对路径>'
```

`--native-first` 必须根据目标环境当前策略和本次确认决定；包生成器默认未启用，不能因省略参数
而悄悄改变现有入口策略。脚本候选版本参数以当前 `--help` 为准，不能用客户端版本号代替。
打包后再修改任何安装器内容，都必须重新生成、验证、审核和打包。

完成条件：候选 `review.json`、推荐清单、不可变脚本摘要一致，记录源提交及未提交差异；
本阶段状态只能写“本地候选”，不能写“已发布”。正式发布前源代码须提交并记录最终提交号；提交另需授权。

## 6. 测试环境发布和真机验收

取得测试发布及设备操作授权后，核实实时短地址、推荐目录、缓存策略和当前文件摘要，
备份本次会改动的入口/清单。历史报告仅用于参考，不能直接沿用旧服务器路径或摘要。
先上传新的不可变脚本并经 HTTPS 读回校验，再原子切换本次授权的可变清单。
仅当入口本身变更时更新入口；保留其他应用、正式环境和历史不可变文件。

用用户实际复制的命令验收，而不只运行本地脚本。受影响平台至少记录：

| 场景 | 必须确认 |
|---|---|
| 空白新装 | 目标版本正确，本地服务稳定启动 |
| 旧版正在运行时升级 | 新版本运行，Token/配置/设备身份保留，无多余旧进程 |
| 同版本重复执行 | 幂等，不重复安装、不改变设备身份 |
| 已装更高版本 | 不降级 |
| 停止后再次安装 | 恢复启动 |
| 下载/校验/启动失败 | 非零退出、明确原因、实际恢复结果与记录相符 |

破坏性失败注入用隔离测试；真机降级、重启、卸载等额外操作必须另行获准。
不支持或无设备的场景标记未验收，不推断通过。设备在线不在安装器成功判定内。

完成条件：公网读回正确、目标场景证据齐备、用户确认测试结果；不能以脚本退出 0 替代启动确认。

## 7. 正式发布与归档

正式发布需要单独明确授权。核对最终提交、审核摘要、验收记录、正式目标和回滚备份；
重复步骤 6 的不可变文件先行、读回、可变清单最后切换流程。
若正式环境来源 URL 与测试环境不同，重新审核对应入口和包装差异，不假设候选字节完全相同。
核对短地址仍指向预期推荐入口，清单引用的安装器真实存在且摘要/大小一致。

完成条件：记录发布前后摘要、实际环境、验证时间、结果和限制；用户交付包含最终命令及更新说明。
只有公网发布与验收均完成才能写“已上线”；测试发布不能改标为正式发布。

## 回滚分支

1. 对比线上当前摘要与本次刚发布的摘要；不同则停止，避免覆盖后续发布。
2. 只恢复本次改动的入口/推荐清单备份；保留不可变脚本和用户配置。
3. 经 HTTPS 读回，确认短地址、清单和安装器恢复到预期组合，记录回滚结果。

推荐清单回滚只影响后续执行安装命令的推荐结果，**不会自动把已升级设备降级**。
设备恢复必须依据该平台实际事务状态另行处理，不能承诺所有平台都能完整回退安装包。

## 安装域名与完整 apps 发布（2026-11-24）

控制台固定访问 `https://run.ddnsto.com`。统一构建复用推荐/站点打包器生成到
`apps/ddnsto/`，不进入 `ddns-server` 或 `ddnsto-static`，不使用 Host 渲染。
构建检查摘要一致性，人工审核与上线授权仍独立进行。Windows 用户入口为 `i.ps1`，
不是 `source/` 中的模板；原生 apps 索引范围保持不变。

先安装正文、再清单/入口、最后控制台；保留历史摘要。现有线上文件本轮不清理。业务环境参数不改变脚本下载源；候选脚本测试分发暂未实施。完整边界和发布命令见 [部署模型](ddnsto-install-deployment.md)，本次证据见 [发布记录](verification/2026-11-20-ddnsto-release-install-domain.md)。运维交接在工作区 `ddnsto-meta/09-playbooks-SOP/DDNSTO一键安装-正式部署说明.md`。本轮仅本地修改，不代表上线。
