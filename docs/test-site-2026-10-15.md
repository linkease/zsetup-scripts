## 复测入口

测试脚本保留原名 `ddnsto/tests/github_linux_canary.sh`，现同时允许固定 GitHub commit 与本测试域名的不可变构建地址。

先用 `ENTRY_URL=... ENTRY_SHA=... sh ddnsto/tests/github_linux_canary.sh --check-entry` 做无安装输入预检。实际测试必须运行在可丢弃 Docker 容器，设置 `DDNSTO_CANARY_CONTAINER=1`、`--cap-add NET_ADMIN`、`--sysctl net.ipv6.conf.all.disable_ipv6=1`，只读挂载测试脚本并使用 `--rm`。不要在宿主上执行安装测试，也不要把真实 Token 放进环境变量、公开命令或日志。

本轮新增 URL 预检用例先失败后通过；Nginx 独立路径配置约束用例也完成红/绿验证。此前隐藏 Token 的固定 GitHub 0.1.8 链接保持原字节；新测试入口与旧链接应分别记录。

复查修正：第一次隔离测试曾按 IP 放行测试域名整个 443，而同域名还承载 API/WebSocket，不能据此宣称云端阻断。增加失败用例后，调整为“获取并校验入口 → 收紧出站 → 执行”，重新在全新容器完成冷安装及重复安装，退出 0。最终结论基于修正后的复测，不隐去初次网络隔离不足。
