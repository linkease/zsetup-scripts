# Managed binary removal candidate

User-approved scope: remove verified owned program versions, markers, current/
previous pointers and the matching user command link; preserve configuration,
user/project data and download caches. Unknown version contents, modified binary
bytes, foreign pointers/commands and an active installer lease fail before any
program deletion. No service stop/unregistration is implied.

Owner entry: `ZSETUP_BIN=/absolute/zsetup sh scripts/remove-managed.sh APP`.
Supported APP: linkspace, ks-cli, kspeeder, user scope only. Existing
ZSETUP_INSTALL_PREFIX and ZSETUP_WORK_DIR must identify the same installation and
lease directory used at install time. Default paths match the user launcher.
Existing sha256sum is required for local removal integrity verification; absence
fails without installing tools or accessing the network. Exit0 means removed or
already absent,2 invalid/unsupported/held lease,11 conflict,12 filesystem failure,
127 missing integrity tool. Configuration/data/cache remain under the prefix;
the prefix itself is deliberately retained. Interrupted/failed filesystem writes
are reported, never claimed to be an atomic whole-installation deletion.

Maintained source is lib/remove-managed.sh; build-entrypoints.py creates the
self-contained scripts/remove-managed.sh from the existing storage and
transaction modules. It is a local candidate resource, not a newly published
zsetup subcommand or installer release. Kai vendors identical generated bytes
with a source and SHA lock; it does not own deletion policy. Published immutable
installers and public release catalog remain unchanged.
