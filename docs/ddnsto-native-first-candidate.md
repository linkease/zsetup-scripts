## 当前顺序

Linux x86_64/aarch64 普通设备：最小安全工作目录 → 严格 HTTPS 下载固定
0.5.0 核心 → 系统 SHA256 校验后才 chmod → 新鲜推荐清单 → 原生 download
校验业务脚本 SHA256/精确大小 → 执行前再次校验 → 原参数/stdin 运行业务入口。

核心摘要从 `bootstrap-policy.sh` 的唯一 `fetch_bootstrap_metadata` 函数在打包时
嵌入，不维护第二张摘要表，不读取 stable、不接受环境提供的核心或下载地址。
核心下载只在原有网络不可用类别时切直接 HTTPS 镜像，校验异常不尝试执行。
业务下载使用 --no-cache、--size、--sha256、--max-bytes、空间保留及总超时。
下载子进程登记到入口既有 cleanup 中，取消时等待其退出，避免先删工作目录。

macOS、DSM、华硕、QNAP 以及未验证的 ARMv7/MIPS 分支仍使用原入口顺序。
这是执行前的平台分流，不是原生下载失败后的自动回退。未开放 Docker 自动选择。
遇到 noexec 或核心不能运行时拒绝，不放宽权限、不自动寻找其他磁盘。
Windows GUI 方案不变；历史 PowerShell 产物仍按原打包协议生成。

## 取舍及未闭合项

- 推荐清单继续严格拒绝所有重定向，保持现有三行协议和每次联网的新鲜度。
- **原生不可变脚本下载会接受 HTTPS 重定向**，坏摘要/大小及 HTTP 降级仍拒绝。
  这是与原入口的行为差异，不能冒充完全等价；打包默认不启用。
  本次审查接受用于测试站，依据及正式上线边界见发布记录。
- 当前 0.5.0 没有独立 checksum 命令，执行前 shell 复验仍保留。
- 核心暂存在每次调用的私有工作目录，不导出为业务执行器的可信缓存。因此本候选
  可能多下载一次核心；未宣称性能已优化或已取消系统下载/摘要依赖。
- ARMv7/MIPS、appliance 核心先行以及全链路信号/恢复的真机矩阵尚未完成。
- 用户要求跳过华硕验收；不得将跳过改成通过。其他设备上一阶段同版本验证不是
  本候选入口的完整设备验收。
