# DDNSTO 分平台推荐安装包配置

`sources/ddnsto/platform-releases.json` 是原生一键安装的客户端推荐版本和产品摘要的唯一维护入口。
覆盖 Linux、OpenWrt、macOS、Windows CLI、群晖和华硕。各平台可以使用不同版本。
本次迁移保持原有 4.2.8 / 群晖 4.2.8-7 和全部已审核产品摘要，不代表新版本发布或设备验收。

## 更新方式

操作步骤、命令、验收条件和回滚统一维护在 [发布 SOP](ddnsto-release-sop.md)。
每次更新使用其中链接的记录模板，本文件只说明配置与代码边界。

## 配置与代码边界

- JSON 只在维护者构建环境读取并编译为版本安装器和 zsetup 配置。设备不增加
  Python、jq 或新的校验依赖，也不修改 zsetup 核心。
- 配置是数据；严格限制版本、摘要、大小及字段，不使用 eval。缺失平台/字段/模板、非法值和无消费者字段均拒绝生成。
- 有 `sources/ddnsto/templates/<文件名>.in` 的文件，其维护源码是模板；
  `sources/ddnsto/<文件名>` 是生成副本。
  生成脚本开头有提示，不应直接修改生成副本。`install-rules.json` 也由模板生成。
  其他没有模板的模块继续直接维护；当前版本自包含入口位于
  `apps/ddnsto/versions/0.3.0/install.sh`。
- 包命名、路径布局、架构映射、解包方式继续由平台模板负责；本次不支持通过配置任意改变安装协议。
  常规版本更新不需修改模板；上游改变包布局或启动参数时仍需要适配代码。
- Linux 与 OpenWrt 已拆开目标版本；OpenWrt standard/lite 当前共用该平台推荐版本。
  华硕六个渠道当前共用华硕推荐版本，但摘要和大小分别维护。
- 获取当前版本、比较版本、不降级、账号/身份保护、事务恢复、启动确认继续保留。
  `managed-service.sh` 对 4.2.8 的已审核健康协议限制是兼容判断，不是推荐版本，不随配置自动扩大支持范围。
- Windows 控制台 GUI 下载链接不由 Windows CLI 配置驱动；Agent 文档统一为
  `apps/ddnsto/install.md` 标准入口。
  Docker 的历史显式安装能力及镜像 pin 也不在本次原生默认流程配置范围内；QNAP/Unraid 未因此新增自动安装能力。

## 安全和发布限制

### OpenWrt 空间预算（安装器 0.3.5 本地候选）

OpenWrt 各主包和 LuCI/语言包增加 `_download_size`、`_installed_size`，单位字节。
与对应版本和 SHA-256 一起维护，不能仅更新版本/摘要后沿用旧大小。
`installed_size` 为包声明值与按 4 KiB 取整的包内文件/目录占用估算的较大值；
这不是针对所有闪存文件系统的精确测量。元数据在维护端审核、编译，设备不需要解包解析工具。

当前预算为 `2 × 三包下载大小 + 三包安装大小 + 4 MiB 元数据工作余量`，
再加 10% 向上取整和 8 MiB 保留空间。第二份下载大小覆盖包管理器压缩缓存。
已有安装/缓存已计入当前已用空间，不预先抵扣将来可能释放的空间。
依赖包、仓库索引和并发写入仍可能超过余量，不宣称预算通过就必定安装成功。

保留低于 900 MiB 内存优先 lite 的规则；普通自动选择 standard 时，如果根分区
不足且 lite 的实际预算更低，改选 lite。明确指定 standard 不自动替换；未知空间拒绝。
4.2.8 lite 是临时 Micro 包，不推断每个架构的 lite 都更小，不降级到旧 Zig 包。

默认工作目录且 zsetup 确认 `/tmp` 是内存文件系统时，使用 root 私有的
`/tmp/ddnsto-package-stage` 保存下载缓存、事务、PM 临时文件与索引。
持久分区预算变为 `三包安装大小 + 4 MiB`，再加 10% 和 8 MiB；临时分区仍按
上面的完整预算检查（包含 PM 可能产生的解压副本）。两侧空间分别检查，任何一侧
不足均在安装前报出路径、所需和可用字节；默认 standard 可以尝试两侧预算都更小的 lite。
例如 aarch64/APK/lite 4.2.8：持久分区 24843060 字节（23.69 MiB），
临时分区 35267027 字节（33.63 MiB）。旧文件、已有缓存及运行中的 zsetup 已反映在可用空间中。

临时根目录必须为安全祖先下的 root 私有目录，拒绝符号链接、不安全所有者/权限、
noexec、只读、零 inode；不要求设备安装 stat。保留当前与前一次尝试的已验证下载，
成功或可恢复失败后删除事务临时文件；恢复失败仍保留事务和锁。
UCI 备份继续放在配置同目录，不迁入内存。临时缓存重启即丢失，可重新校验下载。
旧持久缓存不自动删除。显式工作目录或 `/tmp` 存储类型未知/非内存时保留原持久路径和完整预算。
共享包协调器新增默认不改变行为的适配钩子；仅 DDNSTO OpenWrt 启用临时策略。
包管理器归属、LuCI/依赖安装、UCI 保留和 procd 启动逻辑不变。
当前改善是实际包大小预算和自动选择，不等于几 MiB 设备已获支持。

### Linux 低空间回退（0.3.5 本地候选）

Linux 增加 `zig_client_version`、两架构裸二进制大小/摘要和 standard 归档/解包大小。
用户进程模式优先 standard；空间不足时可使用 `ddnsto-zig/ddnsto.x86_64` 或
`ddnsto-zig/ddnsto.arm64`，仍需通过固定 SHA-256、大小和运行时版本检查。
当前审核 Zig 4.2.1，仅对不会导致降级的生产业务环境安装启用；测试环境和明确指定
standard 不自动切换。新装 x86_64 Zig 的业务阶段额外预算约 2.06 MiB，
不包含入口与 zsetup 自举，不意味着整机只需这点空闲空间。
systemd 新装已接入同样的自动选择；标准包按真实大小预算，包含解包、候选副本、
元数据余量、10% 浮动与 8 MiB 保留空间。Zig 使用 1 MiB 保留空间；
sudo 准备额外计入跨用户下载副本，root 再校验冻结的产品选择与权限。
systemd Zig 需要已有 jq；不会在小容量设备自动安装额外依赖。
已有 standard 不自动迁移到 Zig，已有 Zig 不因空间充足自动换回 standard；
跨实现设备身份继承尚未验证。Zig 运行 YAML 由受保护 JSON 派生，不改变管理配置入口。
预算和验证边界见 [systemd 记录](verification/2026-11-26-ddnsto-systemd-budget.md)。
显式历史版本仍使用旧安全上限。OpenWrt 仍只使用 IPK/APK。
实现、预算公式、产品证据和验证限制见 [Linux 进程 Zig 记录](verification/2026-11-26-ddnsto-linux-process-zig.md)。

构建器不访问网络、不生成或采集产品包，也无法从摘要本身证明产品版本或 CDN 可用性。
所有版本改动都必须有真实发布材料和验收依据。生成文件中仍会出现具体版本和摘要，
但它们是统一配置的编译结果，不是第二份人工维护源。

配置修改必须重新构建、审核并发布推荐安装器才生效；仅修改仓库 JSON 不会改变测试站或正式站。
