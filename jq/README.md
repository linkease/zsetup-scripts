# jq managed installer candidate 0.1.0

The owner installer downloads official jq 1.8.2 executables using native zsetup
SHA256/size verification. `artifacts.lock.json` records official release asset
metadata from https://github.com/jqlang/jq/releases/tag/jq-1.8.2. The build never
bundles product binaries or fetches metadata. Version updates require reviewing
that lock and regenerating with `python3 -B jq/build.py`.

`sh jq/jq-install.sh --plan` works without jq and writes nothing. Install with an
existing `ZSETUP_BIN` or the shared jq-independent core bootstrap. Download
operations use the existing core protocol; no Python, service manager or system
package upgrade is involved. jq checks JSON, regex test/match/sub, Unicode and
the exact version before activation.

Default payloads are `~/.local/lib/linkease/jq/versions/V/bin/jq` (`jq.exe` on
Windows); the command is a managed regular copy in `~/.local/bin`. The `current`
file holds a version, not executable configuration. Regular copies avoid Windows
symlink privileges. An existing foreign command, unsafe path, link or held lock
is preserved. `--installer-prefix /ABSOLUTE/PATH` changes only the payload prefix.
The same filesystem holds bounded staged downloads and atomic replacements.
Available space/persistence is not inferred by this portable adapter; storage
inspection belongs to the calling workflow. Disk failures remain native errors.

Repeat installation uses native zsetup SHA cache validation and reruns functional
checks. `--remove` validates the complete owned tree and SHA256 of every version
before deletion; a modified command or unknown file stops removal. Configuration,
projects and unrelated files remain. Offline removal requires sha256sum or
macOS shasum. This is `jq-managed-v1`, distinct from the shared symlink launcher
removal protocol used by Linkspace and KSpeeder products.

`JQ_DOWNLOAD_BASE` may select an explicitly authorized HTTPS release base, for
example the mapping returned by an existing isolated KSpeeder gateway. It cannot
change the pinned artifact name, size or official digest. The installer neither
discovers nor starts a service; the caller owns gateway readiness and routing.
Unverified public mirrors are not registered. Successful client installation is
not sufficient evidence of an accelerated channel.

Windows `jq-install.ps1` embeds the identical shell policy and invokes Git Bash;
it requires existing native zsetup and does not select WSL bash. The native core
provides the machine architecture, including WOW64. The portable policy uses
the established download/SHA/size interface available in 0.4.0; shared automatic
core bootstrap still applies its existing 0.5+ floor. On Windows 10 AMD64/WOW64,
native core 0.4.0 now passes the PS5.1 public-entry install/reuse/removal flow
with a locally staged, hash-checked official jq 1.8.2 artifact. PS5.1 and PS7
also pass help/plan, empty and literal argv, and exit-code checks. The bridge
uses direct Windows process arguments to preserve Bash quoting on both engines.
These checks do not establish other Windows versions/architectures or a new
core release. macOS likewise requires
an available compatible core; a jq artifact does not establish a core release.

The candidate catalog registers Ubuntu, Debian, generic Linux, iStoreOS/OpenWrt
on the four existing core architectures, macOS x64/ARM64 and Windows x64/ARM64/x86.
The official artifact lock inventories additional Linux architectures; their
presence does not establish a zsetup mapping or native support. The catalog
stays within the existing 128-record protocol limit. Other application records
and published immutable scripts remain unchanged. No public activation is part
of this candidate.

Tests: `python3 -B jq/tests/jq_install_test.py /path/to/native/zsetup` exercises
public generated entries with native zsetup and a real HTTPS fixture. Fixture
locks are supplied to the public builder; production has no runtime digest
override. Desktop branch tests run on Linux with executable protocol fixtures;
they do not establish Windows/macOS kernel behavior or PowerShell parsing.

Native entry regression (no downloads or global package installation):

```powershell
powershell.exe -NoProfile -File jq/tests/windows_entry_test.ps1 -Entry C:\candidate\jq-install.ps1 -Core C:\trusted\zsetup.exe -Bash 'C:\Program Files\Git\bin\bash.exe'
pwsh.exe -NoProfile -File jq/tests/windows_entry_test.ps1 -Entry C:\candidate\jq-install.ps1 -Core C:\trusted\zsetup.exe -Bash 'C:\Program Files\Git\bin\bash.exe'
```

The `Entry` must be the public file regenerated by `jq/build.py`; maintain
`windows.ps1`, never patch the generated payload or a consumer copy.
